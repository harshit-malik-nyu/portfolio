# Free local AI lab

CPU compatibility mode: Transformers.js 3.8.1, onnx-community/Qwen2.5-0.5B-Instruct, q8 weights (512,096,557 bytes plus runtime/tokenizer, approximately 550 MB total). Uses single-thread WASM in a worker without SharedArrayBuffer or WebGPU. The model chooses a single tool-menu token using constrained token decoding; the runtime maps it to fixed, validated arguments. The final evidence brief is assembled from retrieved records and actual tool outputs, not model-generated prose. The application requires evidence reads and relevant analytical checks, prevents repeated actions, and limits voluntary tool choices. This narrower planner avoids requiring a small model to generate multi-field JSON or a reliable prose synthesis. CPU initialization has been verified; see ai-evaluation.md for observed quality failures and subsequent tests.

Runtime: WebLLM 0.2.86 from version-pinned jsDelivr. Model: Qwen2.5-1.5B-Instruct-q4f16_1-MLC from the upstream MLC model catalog. GPU requirement in that catalog is 1629.75 MB; UI recommends 2 GB available. Download is approximately 1 GB. Actual memory and transfer vary. No billing service is used. Browser storage, bandwidth and electricity are still used.

The model selects JSON actions, real shared tools run, and results are fed back into subsequent model turns. This is a bounded agent loop, not native function-call support or a deterministic routing script labelled AI. Actions: evidence search/read, population comparison, synthetic event audit, and explicitly attached visitor CSV audit. Maximum five model turns; 500 tokens per turn; 800-character question. Evidence IDs must have been retrieved; this verifies provenance, not semantic accuracy. A small model may still reason incorrectly or fail to finish. Failed outputs are not replaced with canned AI answers.

Questions are not sent to a hosted inference provider. Initial model/runtime downloads contact jsDelivr, Hugging Face and the upstream MLC model-library host, which receive ordinary request metadata. Optional caching is controlled by WebLLM/browser. Stop terminates the worker and releases its GPU resources; downloaded cache may persist. Attached CSV is audited locally. Only counts, fixed contract findings and record numbers reach the model; raw rows and identifiers are withheld and omitted from exports. An attached-input audit is mandatory before an answer, and a synthetic audit cannot substitute for it. CPU mode then offers the model a choice to finish, inspect reporting evidence, or inspect recovery evidence based on the tool result. The trace identifies application-required and model-selected actions.

Compatibility: secure context, WebGPU and sufficient memory. Devices without shader-f16 use the upstream q4f32_1 variant (catalog estimate 1888.97 MB). The page checks required GPU features before downloading. Setup times out at ten minutes and inference at three minutes. The portfolio and deterministic workbench remain usable without the model.

Validation: Node contract tests cover real tool execution, citation provenance, unknown actions, cancellation, malformed output and bounded looping. Model responses in those tests are injected fixtures, not live inference. Actual model quality requires compatible-hardware testing and is not established by passing contract tests.

Primary references: https://webllm.mlc.ai/docs/user/basic_usage.html and https://webllm.mlc.ai/docs/user/advanced_usage.html .

Live release check: Vercel deployment succeeded. Prompt buttons and no-download initial state were verified in the live UI. The cloud test browser returned no usable WebGPU adapter; real-model inference could not be validated in that environment. This is an experimental feature, not a verified cross-device AI release.

Follow-up safeguards: answers citing the ledger must first execute the population calculator; answers citing the event audit must first execute a valid audit (the actual input when CSV is attached). An early answer is sent back to the model for correction within the same five-step budget. These gates establish execution, not the semantic correctness of generated text. During inference the submitted question and prompt controls are locked, and the original question remains visible with its results. Contract suite: 63 passing tests, including repair, failed-audit, attached-input privacy, and follow-up choice cases.
